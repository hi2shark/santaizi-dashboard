# 服务器管理

进入管理后台的 **服务器** 页面（`/admin/servers`）可以查看所有已接入的 Agent。

## 添加服务器

1. 点击 **添加服务器**。
2. 填写信息：
   - **名称**：展示用的服务器名称
   - **连接密钥**：由 Dashboard 生成，管理员可随时查看和复制
   - **标签**：用于前台分组展示
   - **排序权重**：权重越大越靠前
   - **对游客隐藏**：开启后未登录用户看不到该服务器
   - **启用 DDNS**：配合 DDNS 配置自动解析域名
   - **公开备注**：使用账单、套餐和展示信息表单维护，也可在高级模式编辑 JSON
   - **流量策略**：为入站、出站或总流量配置累计/周期额度与通知
3. 保存后在安装弹窗选择监控预设、指标、服务探测和 NAT，再复制命令到目标机器执行。

## 服务器操作

在服务器卡片或列表操作列中可以进行：

- **编辑**：修改服务器信息
- **查看连接密钥**：随时查看、复制密钥和重新生成安装命令
- **重置连接密钥**：生成新密钥后清洁安装 Agent
- **可用性历史**：查看该服务器的离线历史
- **删除**：移除服务器及其相关数据

## 排序与分组

- **快速改序**：列表「排序权重」列可直接修改数字，失焦或回车后立即保存；权重越大越靠前
- **分组管理**：工具栏打开分组管理，可对已有 `tag` 分组重命名、合并或清空（清空后显示为 `default`）
- 编辑服务器时，分组字段可从已有分组中选择，也可输入新名称

## 批量操作

- **批量修改分组**：选中多台服务器后统一修改标签
- **批量删除**：选中多台服务器后统一删除

## 服务器离线历史

离线历史会记录每台服务器从“在线”到“离线”再到“恢复”的完整过程，并尝试判断离线原因。

### 入口

- 服务器列表页点击 **可用性历史**
- 在 `/admin/servers` 的服务器操作菜单中打开“离线历史”抽屉

### 统计指标

页面顶部展示：

- 最近 24 小时离线次数
- 最近 7 天离线次数
- 最近 30 天离线次数
- 最近 30 天总离线时长
- 最近 30 天可用率
- 最长离线时长

### 离线记录字段

| 字段 | 说明 |
|------|------|
| 开始时间 | 第一次判定为离线的时间 |
| 恢复时间 | Agent 重新上报的时间 |
| 持续时间 | 从开始到恢复的时长 |
| 原因 | `机器重启` / `网络断线 / 上报中断` / `原因未知` 等 |
| 离线阈值 | 触发离线判定的时间阈值 |
| 离线前 IP | 上次在线时的 IP |
| 恢复后 IP | 恢复上报时的 IP |

### 离线原因判定逻辑

系统根据 Agent 上报的 `BootTime` 和 `Uptime` 判断：

- 如果恢复后的 `BootTime` 大于离线前，或 `Uptime` 小于离线前 → 判定为 **机器重启**
- 否则 → 判定为 **网络断线 / 上报中断**
- 如果关键字段缺失 → 判定为 **原因未知**

### 配置离线历史

在 **设置** 页面（`/admin/settings`）可调整：

| 配置项 | 说明 |
|--------|------|
| 启用离线历史 | 总开关 |
| 离线阈值 | 超过该时间未上报即判定为离线（秒，最小 10） |
| 检测间隔 | 离线检测任务的执行间隔（秒，最小 5） |
| 保留天数 | 超过该天数的离线记录自动清理 |
| 离线通知 | 离线时是否发送通知 |
| 恢复通知 | 恢复时是否发送通知 |

### 管理离线记录

超级管理员可以：

- 删除单条离线记录
- 通过 API 手动清理历史：`POST /api/offline-history/cleanup`

> Dashboard 每天 03:30 会自动清理超过保留期的离线记录。

## Agent 能力

安装弹窗提供 **标准·云**、**标准·物理**、**轻量**、**仅存活** 四个预设，并允许单独调整 CPU/负载、内存/Swap、磁盘、网络流量、连接数、进程数、温度、GPU、主机信息、IP/位置、HTTP/ICMP/TCP 探测和 NAT。开启 IP/位置时可填写网卡、位置识别码与 IPv4/IPv6 偏好。心跳与可靠节点身份始终启用；内网穿透默认关闭。

禁用的指标在 API 中表现为“未采集”，不会显示为数值零。Dashboard 不提供远程命令、终端、文件管理或远程更新能力。
