# 服务器管理

进入 **服务器器** 页面（`/server`）可以查看所有已接入的 Agent。

## 添加服务器

1. 点击 **添加服务器**。
2. 填写信息：
   - **名称**：展示用的服务器名称
   - **Secret**：Agent 通信密钥，可自动生成或手动填写
   - **标签**：用于前台分组展示
   - **排序权重**：权重越大越靠前
   - **对游客隐藏**：开启后未登录用户看不到该服务器
   - **启用 DDNS**：配合 DDNS 配置自动解析域名
   - **公开备注**：前台展示给游客的备注
3. 保存后复制 **一键安装命令** 到目标机器执行。

## 服务器操作

在服务器卡片或列表操作列中可以进行：

- **编辑**：修改服务器信息
- **重置 Secret**：重新生成密钥，生成后需要在 Agent 侧更新配置
- **强制更新**：触发 Agent 自动升级到最新版本
- **终端**：打开 Web Terminal（需要 Agent 在线）
- **文件管理**：打开 Web 文件管理器（需要 Agent 在线）
- **可用性历史**：查看该服务器的离线历史
- **删除**：移除服务器及其相关数据

## 批量操作

- **批量修改分组**：选中多台服务器后统一修改标签
- **批量删除**：选中多台服务器后统一删除

## 服务器离线历史

离线历史会记录每台服务器从“在线”到“离线”再到“恢复”的完整过程，并尝试判断离线原因。

### 入口

- 服务器列表页点击 **可用性历史**
- 直接访问 `/server/offline-history?server_id=<服务器ID>`

### 统计指标

页面顶部展示：

- 最近 24 小时离线次数
- 最近 7 天离线次数
- 最近 30 天离线次数
- 最近 30 天总离线时长
- 最近 30 天可用率
- 最长离线时长

### 离线记录字段

| 字段 | 说明 |
|------|------|
| 开始时间 | 第一次判定为离线的时间 |
| 恢复时间 | Agent 重新上报的时间 |
| 持续时间 | 从开始到恢复的时长 |
| 原因 | `机器重启` / `网络断线 / 上报中断` / `原因未知` 等 |
| 离线阈值 | 触发离线判定的时间阈值 |
| 离线前 IP | 上次在线时的 IP |
| 恢复后 IP | 恢复上报时的 IP |

### 离线原因判定逻辑

系统根据 Agent 上报的 `BootTime` 和 `Uptime` 判断：

- 如果恢复后的 `BootTime` 大于离线前，或 `Uptime` 小于离线前 → 判定为 **机器重启**
- 否则 → 判定为 **网络断线 / 上报中断**
- 如果关键字段缺失 → 判定为 **原因未知**

### 配置离线历史

在 **设置** 页面（`/setting`）可调整：

| 配置项 | 说明 |
|--------|------|
| 启用离线历史 | 总开关 |
| 离线阈值 | 超过该时间未上报即判定为离线（秒，最小 10） |
| 检测间隔 | 离线检测任务的执行间隔（秒，最小 5） |
| 保留天数 | 超过该天数的离线记录自动清理 |
| 离线通知 | 离线时是否发送通知 |
| 恢复通知 | 恢复时是否发送通知 |

### 管理离线记录

超级管理员可以：

- 删除单条离线记录
- 通过 API 手动清理历史：`POST /api/offline-history/cleanup`

> Dashboard 每天 03:30 会自动清理超过保留期的离线记录。
