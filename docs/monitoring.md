# 服务监控与告警

## 服务监控

进入管理后台的 **服务监控** 页面（`/admin/services`）可以创建对目标地址的可用性监控。

### 监控类型

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| HTTP GET | 发送 GET 请求，根据状态码判断可用性 | 网站/API |
| ICMP Ping | ICMP 探测 | 服务器连通性 |
| TCP Ping | TCP 端口连通性测试 | 端口服务 |

### 创建监控

1. 点击 **添加监控**。
2. 填写：
   - **名称**：监控项名称
   - **类型**：HTTP / ICMP / TCP
   - **目标**：URL、IP 或 `IP:端口`
   - **检测间隔（秒）**：两次检测之间的时间
   - **通知组**：触发告警时使用的通知方式
   - **覆盖范围**：全部服务器 / 仅特定服务器 / 忽略特定服务器
   - **延迟下限/上限**：可选，延迟超出范围时触发告警
   - **在服务页展示**：是否在前台服务页面显示
3. 使用可搜索穿梭框选择参与探测或排除的服务器。只有声明了相应 HTTP、ICMP 或 TCP 探测能力的 Agent 才会收到请求。
4. 保存后监控会立即开始执行。

### 监控结果

- 在 **服务** 页面查看最近 24 小时可用率、平均延迟
- 点击监控项可查看历史曲线
- 通过 API 获取历史：`GET /api/v1/monitor/:id`

## 告警规则

告警规则用于根据服务器自身指标触发通知。

### 进入方式

在管理后台独立的 **告警规则** 页面（`/admin/alerts`）管理规则；通知渠道仅负责消息发送，两者不会混在同一个编辑器中。

### 规则类型

| 类型 | 说明 |
|------|------|
| `cpu` | CPU 占用率 |
| `memory` | 内存占用率 |
| `swap` | Swap 占用率 |
| `disk` | 磁盘占用率 |
| `net_in_speed` / `net_out_speed` / `net_all_speed` | 入站/出站/总网络速率 |
| `offline` | 服务器离线 |
| `load1` / `load5` / `load15` | 系统负载 |
| `tcp_conn_count` / `udp_conn_count` | TCP/UDP 连接数 |
| `process_count` | 进程数 |
| `temperature_max` | 最高温度 |
| `gpu` | GPU 使用率 |

累计和周期流量配额在服务器编辑器的 **流量策略** 分区中管理，不属于通用告警规则。

### 规则参数

- **名称**：规则名称
- **类型**：上述指标类型
- **最小值 / 最大值**：触发阈值
- **持续周期**：连续多少次检测满足条件后触发
- **通知组**：使用哪种通知方式
- **覆盖范围**：对哪些服务器生效
- **触发模式**：
  - `0` 始终触发：每次满足条件都发送通知
  - `1` 单次触发：同一轮异常只发送一次

### 告警恢复

当指标回到正常范围后，系统会自动发送恢复通知（取决于通知方式配置）。
